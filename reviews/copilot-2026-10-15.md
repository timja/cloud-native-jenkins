# Copilot review of the core stack, round 2 (timja/jenkins #139–#162, timja/jep#4), 2026-10-15

Copilot reviewed each PR again after round 1 ([copilot-2026-10-14.md](copilot-2026-10-14.md)). As before, nothing was replied to on GitHub: this is the record of each comment and what came of it. Fixes went on the branch that introduced the code, with tests, and the stack was rebased after each group.

**134 comments:** 109 fixed, 1 partly fixed, 11 fixed later in the stack, 5 documented, 8 not changed (with why).

Outcomes: **fixed** · **fixed later** (#n) · **partly fixed** · **documented** · **not changed** (the comment does not hold, or repeats one already handled).

## Design questions, decided 2026-10-15

1. **#141, rename/move vs concurrent saves: item monitors only.** The moved item's monitor is held across the store move, the directory move and the parent update. Saves of that item take the same monitor. Children saved meanwhile are not covered, which the javadoc says.
2. **#154, fields omitted on reload: null missing synced fields.** `PersistenceStores.clearRemovedFields` nulls top-level fields that the object serialises now but the new version lacks. It is used by `Jenkins`, descriptors and `User`.
3. **#150, queue ids taken under the queue lock: make it rare.** A pool of 64 ids is filled at startup and refilled as a range in one store call (`ClusterQueue.nextIds`). The store call under the queue lock remains only as the documented fallback.
4. **#155, confidential keys vs `owns()`: opt-in method.** `PersistenceStore.storesConfidentialKeys()` defaults to false. cluster-postgresql overrides it to true.
5. **JEP-252, asymmetric partitions: document now.** Only publication is fenced. A bounded self-fence is listed as future work.

## Security

These weaknesses were introduced by the stack, so they were fixed like any other bug:
- #161: the secrets copy-down accepted any store-listed name without `/`, and wrote through links. It now accepts only plain key names and content that is a key, written via a temp file and never over an existing file or link.
- #162: `ItemFiles.take` wrote any path a manifest named inside the item directory. `ItemUuids` let posted configuration take another item's identity.

## Also changed

- **Not in the triage:** `BuildRecords.republish` now writes conditionally on the version it read (#145, already recorded in round 1's notes).
- **#156 commit retitled:** "Keep deletion markers for an hour, and drop a folded queue item itself" became "…, and fail the queue race test if its other thread fails". The queue fix lives on #150.
- **Test race (#158):** `PersistenceStoreItemConfigTest.conflictingWriteIsDetected` now waits for the applier.
- **Formatting and a slow test:** an unused import was removed on #150, and an import was reordered on #160 (so #162's import-order commit went away). `SharedQueueTest` now waits up to 30 seconds for the mirror; it took more than 5 seconds on a loaded machine.

  - `e4d3d41`: protocol floor, backup.sh header.
  - `8ecb2fb`: `storesConfidentialKeys`.
