## Design questions: decided (2026-10-14) and done
1. Move: claim the destination first (#145).
2. Publishing: only while holding the lease, atomically where the store can (#149; cluster-postgresql in one transaction).
3. Queue lock: held as briefly as possible: no store call under it (#150, with #151/#157 moved off it too; ids taken ahead).
4. `move` returns the versions (#141; cluster-postgresql).
5. Links to builds running elsewhere: never a 404 (#160/#162: a page for the build, with its console as shipped).
6. REST: a separate property, `buildsElsewhere` (#161). A cluster-wide view of builds (all controllers) could come from the cluster plugin later if needed.
