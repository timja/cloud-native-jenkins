## Design questions, decided 2026-10-17

1. **#140, cold start: parallel load, skip needless reads.** With `PARALLEL_LOAD`, items that exist only in the store load in parallel inside the existing reactor task, and `storedItemNames(dir, skip)` no longer reads items already present locally. A batched SPI call (one query in cluster-postgresql) is a follow-up.
2. **#142, a move whose destination folder is gone: take the source out.** When the source's config is no longer stored, the stale local item is taken out as a placeholder is (`ItemChangeApplier.takeOut`), and later events load the destination from the store.
3. **#145, overlapping moves: claim, then check.** After claiming, a move checks the `.moving` claims of every ancestor of its source and destination and any below its source; an overlapping move fails with a conflict. **#148, deletion cleanup vs a job renamed or recreated onto the name:** cleanup applied from elsewhere deletes only entries at versions this controller saw for the deleted job.
4. **#145, claim lapse: when its owner is gone.** A move claim lapses when its origin is no longer live (from #147); the 10-minute age rule remains only for stores that do not report membership.
5. **#154, user `IdStrategy` change: make it work.** `User.rekey` moves users through the store, store-only users included, and other controllers reload users when the strategy changes remotely.
6. **JEP-256, runtime plugins on a fresh home: fetch, then restart once.** An early initializer in the cluster plugin fetches and verifies the cluster's runtime-installed archives on a fresh home and restarts once, before anything is loaded.

## Security

These weaknesses were introduced by the stack, so they were fixed like any other bug:
- #153: deleting a user or node followed a symlinked directory to the target's `config.xml`. Only the routed store key is deleted now, and local files go with `Util.deleteRecursive`.
- #156: with `ALWAYS_REMEMBER`, API-token requests got a remember-me cookie that outlived the token; it now applies only to requests without an `Authorization` header. A stale protected-password form could restore another user's old hash; it is now accepted only if the hash is still current.
- #162: a deleted user's shared files were inherited by a new user with the same id; they are deleted with the user.
- cluster-plugin: plugin names read from the store at boot are checked to be plugin short names before they are used as file names.

## Also changed

- **Open item from round 2 (#161):** a job deleted and remade elsewhere now gets the old job's cleanup: a failed deletion is applied before a newer write of the key.
- **Comments:** `StoredBuildNumberAssigner` notes that it calls the store under the queue lock, the other exception besides the queue-id fallback (#150). `User.changedElsewhere`'s javadoc is back on the method (#162).
- **cluster-plugin:** `40b7f4e` (forwarding fallback only for GET/HEAD or connect failure, else 504), `2a09f48` (boot fetch and restart, disabled plugins keep their archive, `EarlyStoreReader`), `84ac070` (claim checks the pin read).
- **JEPs (timja/jep#4):** `832c712`.
